# Post-v0.2.0 work plan

Status: in progress.

Context: v0.2.0 shipped (release `e889eee`, 4 platform binaries + SHA256SUMS, 8 GGUF repos live). After release, three gaps remain and one capability was deliberately deferred. This plan tracks them.

---

## 1. GPU CI — DEFERRED

**Status:** explicitly deferred. Tracked here so it isn't lost.

### Why deferred

- **CUDA:** requires a `linux_4_core_gpu` larger runner (Tesla T4, $0.052/min). The `espetro` org has no larger runner configured (verified: `gh api /repos/espetro/dinov2.cpp/actions/runners` returns 404, org-admin scope required; Settings → Hosted runners has no GPU entries). Without org-admin action the CUDA job queues forever. **Blocked on infra, not code.**
- **Metal:** would only require a `-DGGML_METAL=ON` cmake flag in `release.yml:146-152` (`-DGGML_METAL_EMBED_LIBRARY=ON` is already the ggml default when Metal is on). No CI infrastructure needed. Was deferred anyway because v0.2.0 shipped successfully on CPU and the priority was test/benchmark infrastructure.

### What exists today (already wired, just not exercised)

- `dinov2.cpp:23-29` — `#ifdef GGML_USE_CUDA` / `GGML_USE_METAL` includes are already in the consumer.
- `dinov2.cpp:227-247` — CUDA → Metal → CPU fallback chain is already in `dino_model_load`.
- `ggml/src/CMakeLists.txt:428-438` — `ggml_add_backend()` PUBLIC-exports `GGML_USE_<BACKEND>` to consumers, so `target_link_libraries(inference PUBLIC ggml)` at `CMakeLists.txt:53` requires zero CMakeLists.txt edits to opt into any backend.
- `ggml/include/ggml-cuda.h` + `ggml/include/ggml-metal.h` are PUBLIC-exported by the `ggml` target (via `ggml/src/CMakeLists.txt:607-608` PUBLIC-export of `${CMAKE_CURRENT_SOURCE_DIR}/../include`).

So adding GPU support is a one-flag YAML change for Metal, and a one-flag + larger-runner infra change for CUDA.

### Re-enable checklist (when the time comes)

**For Metal (small, ~30 min):**
1. Add `-DGGML_METAL=ON -DGGML_METAL_EMBED_LIBRARY=ON` to `release.yml:146-152` (macos-arm64 job).
2. Verify the build still passes (the `.metallib` is auto-embedded into the binary, so archive contents don't change).
3. Optional: rename the existing `macos-arm64` archive to `macos-arm64-metal` to make the backend explicit, and update README download table.

**For CUDA (medium, ~4-8 h):**
1. Org admin configures a T4 larger runner in org Settings → Hosted runners; pick a custom label (recommended: `gpu-linux-t4`).
2. Add a new `ubuntu-x64-cuda` job to `release.yml` with `runs-on: gpu-linux-t4`, `container: nvidia/cuda:12.8.1-devel-ubuntu24.04`, `options: --gpus all`, `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=75-real`.
3. Add a smoke test: download the smallest GGUF (`dinov2-small` f16, ~50 MB) from `dinov2-cpp-core/dinov2-small-gguf` and run one forward pass; assert `using CUDA backend` in stderr. (Note: the HF repo slug dropped the `-vit-...-patch14` segment relative to the local `models/dinov2-vit-{size}-patch14/` directory naming; the C++ loader still uses `dinov2-vit-{size}-patch14` as the on-disk model label.)
4. Update SHA256SUMS aggregator and README download table.

### Cost reality check

- Metal: zero additional cost (macos-latest runner is already in the matrix).
- CUDA: ~$0.50 per release cold build, ~$0.13 warm. Trivial.

## 2. Test coverage — WORKSTREAM A (in progress)

Currently `tests/` covers only `src/image.cpp` (13 TEST_CASEs). `dinov2.cpp` / `quantize.cpp` / `inference.cpp` have zero direct coverage. Adding unit tests for the highest-ROI pure functions, no fixtures required.

### Next 5 TEST_CASEs (half a day, ~95 LOC, runs in existing `sanitize` job)

1. **`do_quantize` matches `.*weight` and 2D shapes** (`dinov2.cpp:212`, ~15 LOC) — feed hand-built `ggml_tensor` stubs (`proj.weight` 2D → true, `cls_token` 1D → false, `layernorm.bias` 1D → false, `attention.qkv.weight` 2D → true). Catches regex/shape-gate regressions.
2. **`interpolate_pos_embed` identity when grid matches img_size** (`dinov2.cpp:148-167`, ~20 LOC) — input 224/14 = 16×16 grid, expect exact copy of `(16*16+1) * hidden` floats. Catches off-by-one in CLS skip.
3. **`interpolate_pos_embed` changes size when grid differs and preserves CLS** (`dinov2.cpp:168-209`, ~30 LOC) — input 518/14 = 37×37 grid, expect output size `(37*37+1) * hidden` and CLS slice identical. Catches bilinear direction sign flip.
4. **`dino_hparams` default math: `n_img_embd==16` for 224/14** (`dinov2.cpp:35-49`, ~10 LOC) — also assert `n_enc_head_dim==64` for hidden=768/12 heads. Catches default-value regressions.
5. **`dino_preprocess` pads non-aligned input to next patch-multiple** (`dinov2.cpp:126-145`, ~20 LOC) — feed 100×50 RGB image with patch_size=14, expect 112×56 output (8 patches × 4 patches). Catches the zero-coverage fallback branch at lines 132-144.

All run in the existing `build.yml:47-70` `sanitize` job (which already runs `ctest --test-dir build-sanitize --output-on-failure`). **No CI change needed.**

### Next batch (after the 5 ship, half-day follow-up)

Requires a synthesized GGUF fixture builder (~3-4 h, no HF download in CI):
- `tests/fixtures/synth_model.{h,cpp}` — builds a tiny ViT-shaped GGUF (hidden=384, layers=2 instead of 12) via `gguf_init_empty` / `gguf_set_val_u32` / `gguf_add_tensor` with small-init-scale Gaussian weights. ~50 LOC.
- `dino_model_load reads hparams from GGUF KV` — assert `model.hparams.hidden_size`, `patch_size`, `img_size`, `num_register_tokens`, `ftype` all populated from KV.
- `dino_model_load populates tensors map with expected names` — assert `embeddings.cls_token`, `embeddings.position_embeddings`, `embeddings.patch_embeddings.projection.weight`, `layernorm.weight`, all 12 × `encoder.layer.{i}.attention.attention.qkv.weight` exist with non-null `data`.

### Out of scope (for now)

- **`dino_params_parse` testing** — requires refactor: function calls `exit(0)` on `-h`/unknown at `dinov2.cpp:795,799`, killing the test binary. Change return type to enum (`PARSE_OK | PARSE_HELP | PARSE_ERROR`), let `main` call `exit`. Mechanical ~10 LOC, then 4 test cases become trivial. Defer to avoid touching `inference.cpp` in the same PR as new tests.
- **`dino_predict` shape+finiteness tests** — needs the synthesized fixture AND careful backend cleanup in the test process. Defer to the next-batch follow-up PR.
- **`dino_model_quantize` round-trip** — requires real weights, F32 reference recording, cosine-similarity check. Separate large item (~6-8 h, gated by `RUN_INTEGRATION_TESTS=1` in CI).

## 3. Benchmark infrastructure — WORKSTREAM B (in progress)

Currently `benchmark_results.txt:1-8` is an acknowledged stub (5-6 ms / 14-15 MB; numbers don't even match `docs/benchmarks.md` which says 64ms on M1). `docs/benchmarks.md` has real-looking but unreproducible numbers tied to a machine not in this repo's CI.

`scripts/benchmark.sh` (140 lines) is half-broken: works, but relies on a `sed`-extracted stderr line for timing and an external `gtime` for memory. `inference.cpp:55-82` does single-shot timing only, no `--bench` flag.

### One-PR deliverable (~150 LOC net code + ~30 min CI)

1. **`dinov2.h:60-70`** — add `bench_repeats` / `bench_warmup` / `bench_json` to `dino_params`. ~4 lines.
2. **`dinov2.cpp:773-804`** — extend `dino_params_parse` to recognize `--bench`, `--bench-runs N`, `--bench-warmup N`, `--bench-json`. ~10 lines.
3. **`dinov2.cpp:753-771`** — extend `print_usage` with the new flags. ~4 lines.
4. **`inference.cpp:55-82`** — wrap the existing timed block in a warmup-then-timed loop. Compute mean/stddev/min/max over `bench_repeats` runs. Emit either markdown row OR JSON to stdout. Sample peak RSS via `getrusage(RUSAGE_SELF).ru_maxrss` between iterations. ~30→50 lines.
5. **`scripts/benchmark.sh` → `scripts/bench.sh`** — refactor in place; keep backward-compatible positional mode for local users. Add `--models <csv>`, `--quants <csv>`, `--repeats <n>`, `--out <path>`, `--aggregate <inputs> --out <path>`. Quantize only when `--quants` is non-empty and not `f16`. Write the markdown table to `--out` instead of stdout. In `--aggregate` mode, concatenate per-platform tables with a platform header above each. ~80 lines delta.
6. **`benchmark_results.txt`** — regenerate from CI runs. Four platform rows × 4 model sizes (S/B/L/g) × peak RSS = ~20-cell table. Methodology header: ggml version, n_repeats, image, f16 baseline.
7. **`docs/benchmarks.md`** — rewrite. Keep the model-vs-PyTorch comparison section (it's qualitatively useful). Drop the "100-run on 14900HX" unreproducible claim. Replace the placeholders with the regenerated `benchmark_results.txt` table. Add a "Methodology" section pointing at `bench.sh`. Add a "Caveats" section: no batching, no KV cache (these are DINOv2's actual constraints, not excuses).

## 4. Manual-trigger bench CI job — WORKSTREAM C (depends on B)

### Decision: ship it

**Yes-but.** Full content drafted (`.github/workflows/bench.yml`, ~150 LOC YAML) — copies the existing patterns from `convert-and-publish-gguf.yml` for HF auth + `/mnt` cache, and from `release.yml` for the build step.

### Triggers

- `workflow_dispatch` only (manual click in Actions tab) — **no PR triggers, no push triggers.**
- Plus a monthly schedule `0 7 1 * *` as a "stale-data alarm" (if you forget to click run for a month, the schedule does).

### Workflow shape

- 4 parallel platform jobs: `ubuntu-latest`, `ubuntu-24.04-arm`, `macos-latest`, `windows-latest`. Each builds + downloads selected GGUFs from `dinov2-cpp-core/*-gguf` + runs `scripts/bench.sh --models ... --quants ... --repeats ... --out bench-<platform>.txt` + uploads per-platform artifact.
- 1 aggregator job: downloads the 4 per-platform files, runs `bench.sh --aggregate ./per-platform/*.txt --out benchmark_results.txt`, then opens a PR via `peter-evans/create-pull-request@v6` against `master` (no bot token needed for public repos) **iff `inputs.open_pr == 'true'`**.

### Inputs

- `models`: comma-separated `small,base,large,giant`. Default `small,base`.
- `quants`: comma-separated `f16,q4_0,q4_1,q5_0,q5_1,q8_0`. Default `f16`.
- `repeats`: integer. Default `5`.
- `open_pr`: boolean. Default `true`.
- `target_branch`: string. Default `master`.

### Cost (per invocation, with user's defaults small+base, f16, 5 repeats)

| Runner            | $/min | Billed min | Cost |
|-------------------|-------|------------|------|
| ubuntu-latest     | 0.008 | ~7.5       | $0.06 |
| ubuntu-24.04-arm  | 0.008 | ~9.5       | $0.076 |
| macos-latest      | 0.080 | ~6.5       | $0.52 |
| windows-latest    | 0.016 | ~8.5       | $0.136 |
| aggregator        | 0.008 | ~1         | $0.008 |
| **total**         |       | ~33 min    | **~$0.80** |

Materially cheaper than the L-sized nightly (~250 min/wk burn, ~$2/wk). Manual-only means **no surprise PRs at midnight**.

### Hard prerequisites (must land in PR B before this workflow file is useful)

- `scripts/bench.sh` must accept `--models`, `--quants`, `--repeats`, `--out`, `--aggregate` flags (not just positional). PR B delivers this.

### Caveats explicit in the PR description

- CUDA skipped (no GH-hosted GPU runners on this org; would need `linux_4_core_gpu`).
- Metal skipped for now (existing release matrix doesn't pass `-DGGML_METAL=ON`; all macos-arm64 rows exercise CPU backend until workstream 1 lands).

### One small build.yml diff

Add `upload-keys: ccache-${{ runner.os }}-${{ runner.arch }}-` to the `ggml-org/ccache-action@v1.2.21` call at `build.yml:34-37` so the bench workflow can `actions/cache` restore `~/.ccache` and reuse hits (~5 min saved per cold bench run).

### Windows-specific gotchas

- `ccache` isn't on the default Windows runner PATH. The bench workflow's Configure step passes `-DCMAKE_C_COMPILER_LAUNCHER=ccache` for all platforms; on Windows this fails. Either drop the launcher on Windows (cleanest) or add `choco install ccache -y` gated on `runner.os == 'Windows'`.
- `jq` isn't on Windows runners by default. The HF revision cache-key step uses `jq`. Either add `choco install jq -y` gated on Windows or rewrite that step to use PowerShell `ConvertFrom-Json`.
